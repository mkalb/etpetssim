# Localization Instructions

Rules for the resource bundles in `i18n` and the localization key constants; repository-wide and Java instructions
still apply.

## Bundle Content

- Keep all production bundles (`messages_*.properties`) in sync: every bundle contains the same keys, and each key has
  the same placeholders in every bundle.
- `.url` keys exist in all bundles; an empty value means that the locale has no link. Their values are
  locale-specific links and are exempt from placeholder parity, because URLs may contain percent-encoding.
- Use indexed placeholders (`%1$s`, `%2$d`, `%1$.0f`); the order of the placeholders in a value may differ between
  the locales. In a value with placeholders, write a literal percent sign as `%%`.
- Label texts carry no trailing colon; views add a separator where a layout needs one (e.g., `LABEL_SEPARATOR` in
  `AbstractObservationView`).

## Wording and Style

Write consistent and clear values: inviting like a game where the table below says so, otherwise neutral and concise.

Each value has one of the following text types. The keys are typical examples; a value whose key matches no pattern
has the type of its use (e.g., a label without suffix). The examples show the target style in en_US.

| Text type    | Keys                        | Form                             | Tone     | Example                   |
|--------------|-----------------------------|----------------------------------|----------|---------------------------|
| Title        | `.title`, `*.section.*`     | noun phrase                      | neutral  | `Selected cell`           |
| Label        | `.label`, `.short`, `.long` | noun phrase; value after a colon | neutral  | `Grid width: 80 cells`    |
| Option       | enum constants              | noun or adjective phrase         | neutral  | `Edges only`              |
| Button       | `control.start`, toolbars   | verb; de_DE infinitive           | neutral  | `Pause` / `Pausieren`     |
| Tooltip      | `.tooltip`                  | imperative; de_DE du form        | inviting | `Draw walls on the grid`  |
| Prompt       | `.prompt`                   | short hint                       | neutral  | `Leave empty for random`  |
| Subtitle     | `.subtitle`                 | what happens in the simulation   | inviting | `Watch sharks hunt fish`  |
| Description  | `.description`              | full sentences                   | inviting | `A wall stops the snake.` |
| Notification | `notification.*`            | full sentences                   | inviting | `The grid is too large.`  |
| Alert        | `alert.*`                   | full sentences                   | neutral  | `An error occurred.`      |
| Help text    | `about.help.*`              | full sentences                   | inviting | `Pick your simulation.`   |
| Argument     | `args.*`                    | imperative; de_DE 3rd person     | neutral  | `Print the version`       |
| Fragment     | inserted values             | single word                      | -        | `unknown`                 |

- Terms: use one term per concept and locale as the glossary `docs/development/localization-glossary.md` lists it,
  and prefer established technical terms. Add a new domain concept to the glossary before using it in a bundle.
- Count metrics: name what they count: an entity by the plural of its glossary term (`Trees`, `Ants`, `Walls`;
  uncountable `Food`), an entity that spans several cells by its whole (`Snakes`, not `Snake heads`), and a cell
  state without an entity term as `<state> cells` / `<Zustand> Zellen` (`Empty cells`, `Visited cells`). The
  adjective for "not dead" is `Living` / `Lebende`.
- Order: write the en_US value first and derive the de_DE value from it, instead of translating word by word.
- Spelling in en_US: American English (`color`, `behavior`, `gray`, `center`).
- Capitalization in en_US: sentence case for all values, including compass directions (`East-northeast`); proper
  names keep their capitalization (`Conway's Game of Life`, `Wa-Tor`).
- Capitalization in de_DE: each value starts with a capital letter and otherwise follows standard German
  capitalization (`Lebend` as an option, `lebend` within a sentence).
- English terms in de_DE: use the common German word where one exists (`Protokoll`, `Gitter`); keep an English term
  that is common in German or has no good German equivalent (`Seed`, `Emoji`, `Layout`), as the glossary lists it;
  join English parts of a compound with a hyphen (`Build-JDK`, `Commit-Datum`).
- Fragments: start in lowercase in en_US (`unknown`, `flag`) and follow standard German capitalization in de_DE
  (`unbekannt`, `Flag`).
- UI elements in running text: name a general element by its lowercase glossary term (`start screen`,
  `control panel`); quote the visible text of a specific element exactly, with straight quotes in en_US and German
  quotation marks in de_DE (`Click "Start"` / `Klicke auf „Starten“`).
- Address form in de_DE: the informal "du" in all values; never "Sie" or "Ihr".
- Tooltips: usually one short sentence (`Füge der ausgewählten Zelle eine Wand hinzu`); in exceptional cases two or
  three sentences, e.g., when the tooltip explains an input format.
- Command-line arguments: follow the usual style of console help texts: a short phrase per argument
  (`Print the version and exit` / `Gibt die Version aus und beendet die Anwendung`); a heading of the argument list
  ends with a colon (`Command-line arguments:`).
- Punctuation: values with full sentences and tooltips with two or three sentences end every sentence with a period;
  all other values end without a period.
- Length: keep buttons, labels, titles, and combo box options short; tooltips and subtitles carry the details. The
  start screen cards and the labels of the configuration and control panels are the tightest places (widths in
  `scene.css`).
- Abbreviations: write `e.g.` in en_US and `z. B.` with a normal space in de_DE; abbreviate maximum and minimum in
  labels as `Max`/`Min` in en_US and `Max.`/`Min.` in de_DE (`Max age` / `Max. Alter`).

## Key Schema

- A key consists of dot-separated segments of lowercase letters and digits, without other separators
  (`gridedgebehavior.blockxwrapy`).
- The first segment names the owner of the key:
    - an application area (`about`, `alert`, `args`, `header`, `start`, `window`),
    - an area shared by the simulations (`config`, `control`, `notification`, `observation`, `simulation`),
    - an enum, named after its type in lowercase (`cellshape`, `gridedgebehavior`); `CompassDirection` uses `compass`,
    - a simulation, named after its package (`conway`, `wator`), followed by its area (e.g., `config`, `entity`,
      `observation`, `toolbar`).
- Use the standard suffixes: `.label` for the type label of an enum, `.tooltip`, `.prompt`, `.title`, `.subtitle`,
  and `.url`; entity descriptors use `.short`, `.long`, `.description`, and `.emoji`.
- Enums and records provide their keys as `java.md` ("Enums") describes; an enum uses the type label `<enum>.label`
  and keys with the same prefix for its constants (`cellshape.triangle`).

## Format and Editing

- Bundles are UTF-8 without BOM, without `\uXXXX` escapes, comments, or blank lines, with one consistent line ending
  and exactly one trailing newline.
- Each line holds one `key = value` entry; the entries are sorted alphabetically by key (case-insensitive), and the
  `=` signs are aligned in one column.
- Add, rename, or remove an entry by hand in all production bundles in the same change; put a new or renamed key at
  its sorted position and pad it so that its `=` stays in the existing column. Do not reorder or re-align existing
  entries by hand.
- Run the `i18n-consistency` skill once before finishing a change to a production bundle. Its report on format and
  parity is read-only; its `fix` mode reformats the bundles (e.g., when a new key does not fit the `=` column) only
  after confirmation by the user.

## Test Bundles

- The test bundles `test_messages_*.properties` (prefix rule in `junit.md`) are fixtures for `AppLocalizationTest`
  and deviate intentionally from the production bundles: `onlyUS` exists only in `en_US`, and `Hello %d` is not
  indexed.
- Only the format conventions apply to them; do not align their keys or placeholders with the production bundles.

## Key Constants

- Place key constants as `java.md` ("Code Style") describes; `AppLocalizationKeys` holds only the keys of `core`, `ui`,
  and the root package, and a simulation-specific key is a private constant of the class that uses it.
- Name a key constant after its key in upper snake case and split compound segments into words
  (`wator.config.sharkmaxage` -> `WATOR_CONFIG_SHARK_MAX_AGE`). A catalog class may name its label keys by role
  instead (`PATTERN_LABEL_KEY_*` in `ConwayPatterns`).
- Sort and test the key constant classes as `java.md` ("Utility Classes") describes; their tests also check that
  every key exists in all production bundles (`junit.md`, "Common Contract Patterns").
- The type Javadoc of a key constant class describes only its own keys.
- Access bundles only through `AppLocalization`.
