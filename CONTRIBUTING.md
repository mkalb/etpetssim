# Contributing

Thank you for your interest in the Extraterrestrial Pets Simulation (etpetssim). This guide explains how to report
bugs, suggest ideas, ask questions, and contribute changes.

## A Single-Developer Project

The project is maintained by a single developer ([mkalb](https://github.com/mkalb)). Responses may take some time,
and there is no guarantee that an issue or pull request is accepted.

## Bugs, Ideas, and Questions

- Search the [existing issues](https://github.com/mkalb/etpetssim/issues) first; add to an existing issue instead of
  opening a duplicate.
- Open a [new issue](https://github.com/mkalb/etpetssim/issues/new/choose) with one of the issue forms: bug report,
  feature request, or question.
- For a bug, include the version and build information from the About dialog (tab "Version"), your operating system,
  and the steps to reproduce it.

## Contact

Use GitHub issues only. Please do not contact the maintainer by email or other private channels about the project.

## Security

Do not report security vulnerabilities in public issues.

## Pull Requests

Pull requests are welcome only after prior agreement in an issue:

1. Open an issue, or comment on an existing one, and describe the change you plan.
2. Wait until the maintainer agrees to the change.
3. Work on a branch in your fork and open a pull request that refers to the issue.

Unsolicited pull requests may be closed without review.

## Language

Write issues, pull requests, commit messages, code comments, and documentation in English.

## AI Tools

The use of AI coding agents is welcome and encouraged. Make sure that your agent follows the coding, documentation,
and localization conventions in [AGENTS.md](AGENTS.md) and the rules in [.claude/rules](.claude/rules) (GitHub Copilot
finds references to them in [.github/instructions](.github/instructions)), so that your contribution keeps the
project's style and conventions.

The section "Maintainer Workflow" in `AGENTS.md` does not apply to contributors.

You remain responsible for every change you submit: review it and make sure that you understand it.

## Build and Test

The README describes the [prerequisites, commands, and application arguments](README.md#run-the-app). The Gradle tasks
for compiling, testing, and building are listed in the section "Platform Baseline" of [AGENTS.md](AGENTS.md).
